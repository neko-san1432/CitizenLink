# Heatmap And Complaint Category Expected Outputs

## Scope
This document defines expected outcomes for large complaint seed runs generated by `scripts/db/generateBulkComplaintSeeds.js` at 20,000 to 50,000 complaints.

Validation targets:
1. Tactical visualization outputs (AI clustering, incident heatmap, individual markers)
2. Complaint category behavior under filters (category_id, subcategory_id, date, status)
3. Ambiguous and adversarial text handling including Others

## Dataset Profile Assumptions
1. Complaints use `category_id` and optional `subcategory_id`.
2. Description text includes English, Tagalog, Bisaya, and mixed-language structures.
3. Description noise includes abbreviation, leetspeak substitutions, misspellings, missing letters, slang, figurative and metaphorical phrases.
4. Others category complaints contain uncertain or mixed-intent narratives.
5. Coordinates remain inside Digos boundary envelope for map visibility.

## Visualization Modes Expected Output

### AI Clustering Mode
Expected output:
1. Cluster overlays are visible immediately after load when data exists.
2. Heatmap layer is not auto-forced on top of clusters.
3. For 20k-50k datasets, summary-style clusters may be used to prevent overload.
4. Cluster labels and group centers remain visible after mode toggle roundtrip.

Acceptance ranges:
1. 20k dataset: at least 40 visible clusters in city-wide view.
2. 50k dataset: at least 80 visible clusters in city-wide view.
3. After toggling to heatmap then back to clusters, visible cluster count should not drop below 80 percent of pre-toggle count for the same filters.

### Incident Heatmap Mode
Expected output:
1. Heat intensity follows complaint density and recency weighting behavior.
2. Removing category filters broadens the hotspot footprint.
3. Applying strict category/subcategory filters narrows hotspots to focused areas.
4. Heatmap remains responsive during high-volume data.

Acceptance ranges:
1. 20k dataset: at least 5 clear hotspot zones on default city view.
2. 50k dataset: at least 8 clear hotspot zones on default city view.
3. Category filter application should visibly reduce hotspot footprint by at least 20 percent for focused categories like Utilities or Traffic.

### Individual Marker Mode
Expected output:
1. Marker mode displays individual complaint points and detail popup metadata.
2. Marker details should include category context and description snippets.
3. Category/subcategory filters should synchronize with marker visibility.
4. Toggling markers off should not re-enable cluster/noise artifacts unintentionally.

Acceptance ranges:
1. Marker count after filter should match API-filtered result set within 0 to 1 percent drift.
2. Marker mode to cluster mode switch should preserve active filters with no blank-map state.

## Filter Behavior Expected Output

### Category/Subcategory Filters
1. Category-only filter must include complaints with null subcategory in that category.
2. Subcategory filter must narrow result sets without breaking map mode rendering.
3. Others category filter must produce visible markers or heat if seeded rows exist.

### Date Filters
1. Last 7 days should show reduced but non-empty city activity for 20k and 50k runs.
2. Last 30 days should preserve major hotspot topology while reducing long-tail clusters.

### Status Filters
1. Pending and in-progress filters should retain stronger active clusters than resolved-only filters.
2. Resolved-only view should show broader historical spread with lower urgency interpretation.

## Performance Expectations

### 20,000 Complaints
1. Initial map render should remain interactive with no permanent blank map states.
2. Mode switching should complete with visible layer results in under 2 seconds on typical dev hardware.
3. Filter apply action should return visible updates in under 2 seconds for common category slices.

### 50,000 Complaints
1. Large-dataset fallback behavior should preserve visible clusters (summary mode allowed).
2. Heatmap should remain the most stable high-volume visualization mode.
3. Mode toggles should preserve selected mode and active filters after refresh.

## Pass-Fail Checklist
1. No default-load regression where heatmap overrides selected cluster mode unexpectedly.
2. Cluster mode remains visible after heatmap roundtrip.
3. Category and subcategory filters produce non-empty outputs when matching rows exist.
4. Others and null subcategory complaints are present and visible under correct filters.
5. At least one hotspot and one cluster remain visible for each major category family when filtered to date ranges with known volume.

## Notes For Seed Validation Runs
1. Run baseline at 20,000 and stress run at 50,000.
2. Capture screenshots for each mode under identical filters.
3. Record cluster count range, hotspot count range, and filter result counts for each scenario family.
4. If ambiguity scenarios over-dominate Others beyond 30 percent, rebalance scenario weights in generator script.
